CLI Reference

The scitex-dataset command-line interface follows the SciTeX 3-level noun-verb grammar:

scitex-dataset <domain> <dataset> <action> [OPTIONS]

See general/03_interface_02_cli/02_subcommand-structure-noun-verb in the SciTeX skills for the underlying convention.

Configuration precedence

Resolution chain (highest first), per general/01_ecosystem_06_local-state-directories:

  1. --config <path> CLI flag

  2. $SCITEX_DATASET_CONFIG env var

  3. <project>/.scitex/dataset/config.yaml

  4. $SCITEX_DIR/dataset/config.yaml (default ~/.scitex/dataset/config.yaml)

Project scope wins over user scope. SCITEX_DIR relocates the user scope atomically. Runtime files (snapshots, caches, logs) live under <scope-root>/runtime/. The dataset index does not: it lives in the shared SciTeX store, which SCITEX_STORE_DSN repoints.

Legacy aliases (hidden, exit code 2)

For users migrating from the pre-3-level CLI:

Old form

New form

fetch-<source> [...]

<domain> <source> fetch [...]

<source> (bare)

<domain> <source> fetch

hf <verb>

general huggingface <verb>

hf-<verb>

general huggingface <verb>

db stats

db show-stats

The legacy commands print a redirect message and exit with status 2.

Live command tree

The full subcommand tree below is rendered directly from the click group via sphinx-click. Regenerate the shipped HTML after CLI changes and check the rendered commands; a source directive alone does not prove that the bundle is current. Per the SciTeX Sphinx spec (audit code PS128), hand-written subcommand prose is forbidden here.

completion install and completion status are current commands, not legacy aliases. Their drop-in behavior is covered by tests/scitex_dataset/_cli/test__completion.py.

scitex-dataset (v0.8.3) — scitex-dataset — unified scientific dataset discovery.

Config resolution (highest first):

ai-for-science

Ai-for-science datasets — CORE-Bench, BixBench, BioMysteryBench.

Usage

scitex-dataset ai-for-science [OPTIONS] [COMMAND] [ARGS]...
biomysterybench

BioMysteryBench — Agentic AI-for-science benchmark: biology-mystery problems with rubric-graded answers (Anthropic; gated full set).

Usage

scitex-dataset ai-for-science biomysterybench [OPTIONS] [COMMAND] [ARGS]...
download

Fetch the upstream biomysterybench snapshot into raw/ as-is.

WARNING: downloads are multi-GB. Run on SLURM, not a login node or CI.

Example:
$ scitex-dataset ai-for-science biomysterybench download
$ scitex-dataset ai-for-science biomysterybench download –full –dataset-root /scratch/datasets

Usage

scitex-dataset ai-for-science biomysterybench download [OPTIONS]

Options

--json

Emit the result dict as JSON.

--dataset-root <dataset_root>

Dataset root holding ai-for-science/ (default: $SCITEX_DATASET_ROOT, nearest project .scitex/dataset, or ~/.scitex/dataset).

--full

Pull the full gated set instead of the small preview (where the benchmark distinguishes them, e.g. biomysterybench). For corebench, the full set is the oracle-driven 90-capsule run: it bootstraps the answer manifests (fetch + gpg-decrypt) then fetches every capsule tarball.

--capsule-ids <capsule_ids>

corebench only: comma-separated NATIVE capsule ids (e.g. capsule-0201225,capsule-0238624) to fetch just those tarballs from the CDN — the oracle URLs are never touched. Overrides the oracle-driven full run.

--verify-integrity

Re-check existing files by sha256 before skipping (opt-in; default skip is by existence, no hashing).

--force

Re-download everything, ignoring what’s already on disk.

prepare

Prepare biomysterybench: download (raw/) + standardize (for_solver/ + eval/) + emit .scitex/dataset/MANIFEST.yaml (id + version + sha256 + mask-seed).

WARNING: includes the multi-GB download step unless –skip-download is given. SLURM-only on shared compute.

Example:
$ scitex-dataset ai-for-science biomysterybench prepare –skip-download
$ scitex-dataset ai-for-science biomysterybench prepare –full –version v1.0

Usage

scitex-dataset ai-for-science biomysterybench prepare [OPTIONS]

Options

--json

Emit the result dict as JSON.

--dataset-root <dataset_root>

Dataset root holding ai-for-science/ (default: $SCITEX_DATASET_ROOT, nearest project .scitex/dataset, or ~/.scitex/dataset).

--version <version>

Snapshot version recorded in MANIFEST.yaml (upstream tag / HF revision / ISO-date).

--skip-download

Skip the upstream pull (raw/ already staged).

--full

Pull the full gated set instead of the small preview.

--verify-integrity

Re-check existing files by sha256 before skipping (opt-in).

--force

Force acquisition where supported and re-extract only identity-qualified capsules. Source/content changes require fresh output destinations.

score

Score a biomysterybench submission against the operator oracle (eval/answers.jsonl; host-side only). Emits one record per task: correct, wrong, abstain, malformed, needs_rubric or invalid_reference. Malformed records include format failure kinds such as schema_invalid; invalid references are not scientific wrong answers.

Example:
$ scitex-dataset ai-for-science biomysterybench score –submission sub.json
$ scitex-dataset ai-for-science biomysterybench score –submission sub.json –json

Usage

scitex-dataset ai-for-science biomysterybench score [OPTIONS]

Options

--json

Emit the result dict as JSON.

--dataset-root <dataset_root>

Dataset root holding ai-for-science/ (default: $SCITEX_DATASET_ROOT, nearest project .scitex/dataset, or ~/.scitex/dataset).

--submission <submission>

Required Path to the agent submission JSON (the uniform array).

standardize

Read the biomysterybench raw/ snapshot; write the agent-visible for_solver/ view (per-capsule dirs + index.jsonl mapper, no answers) + the operator eval/ view (answers.jsonl + evaluate.py).

Example:
$ scitex-dataset ai-for-science biomysterybench standardize
$ scitex-dataset ai-for-science biomysterybench standardize –only capsule-0201225
$ scitex-dataset ai-for-science biomysterybench standardize –json

Usage

scitex-dataset ai-for-science biomysterybench standardize [OPTIONS]

Options

--json

Emit the result dict as JSON.

--dataset-root <dataset_root>

Dataset root holding ai-for-science/ (default: $SCITEX_DATASET_ROOT, nearest project .scitex/dataset, or ~/.scitex/dataset).

--only <only>

Materialize ONLY this capsule’s for_solver/ dir — accepts a friendly id (capsule-NNN) or a native capsule id (e.g. capsule-0201225), resolved via the index.jsonl mapper. The full mapper is still written. Default: all capsules.

--force

Re-extract only identity-qualified existing capsules. Changed or unstamped source/content requires fresh output destinations.

validate

Validate a biomysterybench submission without an oracle: strict JSON types, required fields, unique IDs and exact public assignment membership. Use –tasks for a selected capsule. Optional public answer_type declarations are checked without coercion; absent declarations accept supported JSON. The default index covers the whole catalog; missing default metadata is explicitly shape-only. This never grades answers.

Example:
$ scitex-dataset ai-for-science biomysterybench validate –submission sub.json –tasks for_solver/capsule/task.jsonl
$ scitex-dataset ai-for-science biomysterybench validate –submission sub.json –json

Usage

scitex-dataset ai-for-science biomysterybench validate [OPTIONS]

Options

--json

Emit the result dict as JSON.

--dataset-root <dataset_root>

Dataset root holding ai-for-science/ (default: $SCITEX_DATASET_ROOT, nearest project .scitex/dataset, or ~/.scitex/dataset).

--submission <submission>

Required Path to the agent submission JSON (the uniform array).

--tasks <tasks>

Selected public task.jsonl or capsule directory. Without this, use the whole for_solver index; missing metadata is labeled shape-only.
